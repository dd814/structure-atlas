# 离线图谱模板

先做关系核对，再填写 JSON。将下面命令中的路径换成实际路径。本技能的目录只读，输出放在当前任务的可写目录。

```text
python <skill-dir>/scripts/build_atlas.py <map.json> <output.html>
```

[完整示例](../assets/example.json) 是虚构的工作流程。用作格式样例和渲染检查。

| 位置 | 字段 |
|---|---|
| 顶层 | `title` 标题、`intro` 引导、`nodes` 部件、`edges` 关系、`paths` 阅读路径。 |
| 部件 | `id` 唯一短标识、`title` 标题、`group` 所属分区、`summary` 职责。可选 `position` 为总图里的 `[行, 列]`，从 1 开始，最多 4 列。没设置位置的部件仍能在目录和关联入口打开。 |
| 关系 | `from` 发起方或上游、`to` 接收方或下游、`label` 箭头上的短词、`detail` 说明交接的内容。可选 `kind`：`actual`、`experimental`、`planned` 或 `uncertain`，默认 `actual`。可选 `evidence` 标出资料出处。用 `diagram: false` 把复杂交叉边留在明细列表和部件页。 |
| 细节 | 部件的 `source` 可写文件绝对路径、行号或资料标题。可选 `blocks`，每块有 `title` 和 `summary`，可再填 `source` 和 `code`，后者为可展开的源码或材料摘录。 |
| 阅读路径 | `paths` 的元素包含 `title` 和 `steps`。每步用 `node` 指向部件，`note` 写清本步实际做什么。可以有多条路径，比如用户操作和开发验证。 |

把总图控制在能一眼发现入口、核心交接和出口的规模。优先让相连部件在相邻行列，并用短标签。模版绘制箭头及短标签，完整关系也以文本列在下方。窄屏可用文本关系读方向和交接，无需缩小字。复杂连线若互相遮挡，重新摆放或将次要边移到明细。交叉边较多时，可以改用更合适的图形工具或分图。

生成后用真实浏览器检查总图、路径切换、部件追踪、细节展开和窄屏。脚本会检查编号、布局位置、关系和路径引用，不能验证关系本身是否真实。发布或分享时仅嵌入适合目标受众查看的资料。

## 项目进展

同一个项目保持一个当前 HTML 路径，并在项目内保留可再次生成的 JSON。已有定制图谱继续用它的模板和数据源；接入相同的进展字段或做等价展示。更新时保留历史记录和模块身份，同步改掉已失效的当前说明、状态或关系，便于用户把新版与自己保留的历史快照对照。

`checkpoints` 是可选数组，按发生顺序填写，允许同日多次更新。模板在部件旁显示最近一次变化，独立进展视图按最新在前展示完整记录。每条的「复制讨论上下文」包含项目、部件、进展、依据和可继续讨论的问题，可以粘贴到 Agent。离线页面自带这些信息，源文件更新后刷新已打开的页面即可。

```json
{
  "checkpoints": [{
    "date": "2026-10-18",
    "title": "跑通导入后的第一条路径",
    "changes": [{
      "node": "booking",
      "status": "verified",
      "note": "已走通提交预约和展示结果。",
      "evidence": "本地验收记录 · 提交后返回预约编号，并能在列表查到。",
      "next": "接下来要支持用户自行改期，还是先做取消？"
    }]
  }]
}
```

- `date` 用 `YYYY-MM-DD`。`node` 用已有部件 ID。同一次更新里每个部件合并成一条。
- `status` 选 `verified`（已验证）、`implemented`（已实现待验证）、`blocked`（受阻）或 `planned`（待推进）。`verified` 要有 `evidence`。有可定位的测试、产物或用户决定时，写到 `evidence`。`next` 可填接下来要核对或讨论的具体问题。
- 更新只记看得出结果的变化。处于试验、待核验或有依赖的工作按实际状态标注。当前状态变动时，一起校对受影响的部件摘要、流程或箭头。按已确认的目标路径重新生成，例如 `python <skill-dir>/scripts/build_atlas.py <map.json> <output.html> --force`。检查旧记录仍在、变更跳到对应部件、复制文字和更新日期正确。
